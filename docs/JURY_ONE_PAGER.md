# GIPUZKOA 360 · Una pregunta, un cálculo comprobable

**Problema.** Detectar patrones territoriales exige cruzar datos, fijar criterios y explicar sus límites.

**Destinatario.** Personal técnico municipal y territorial que contrasta municipios antes de profundizar con información sectorial. Sin implantación administrativa ni validación de usuarios acreditadas.

**Solución.** Pregunta → elige operación → cálculo determinista → evidencia → respuesta revisable. El agente admite nuevas preguntas y parámetros; el HTML conserva resultados, no ejecuta conversaciones.

**7 operaciones:** resumen, comparación, envejecimiento, distancia a registros, coincidencia, escenario y fuentes.

**3 fuentes:** Eustat (01/01/2025), geoEuskadi (07/05/2025), Open Data Euskadi (20/09/2026). Fechas distintas.

| Evidencia | Qué cuenta / alcance |
|---|---|
| **88 municipios · 148 registros** | Catálogo preparado completo; registros públicos, no capacidad asistencial. |
| **7 → 4 → 2** | Coincidencia 65+ q0,75 → 75+ q0,80 → 65+ q0,85. El umbral en km no decide los destacados. |

| **72.673/72.673 checks** | Evaluaciones sujeto × propiedad del benchmark definido; no conversaciones. |
| **31.545/31.545 trazables** | Outputs numéricos auditados con periodo, unidad, método y fuentes; no todas las respuestas posibles. |
| **20/20 inyecciones** | Corrupciones deliberadas rechazadas de forma controlada. |
| **1.000 llamadas sostenidas** | Sin deriva ni excepciones en esa secuencia; no garantía indefinida. |

**Límite principal.** Distancia desde un punto municipal no mide tiempo de viaje, capacidad, citas ni necesidad individual.

**Riesgos conocidos.** M-01: escenario extremo de 20.155 caracteres y 66 filas, sin demostración en portal; el caso Aduna es manejable y no se trunca evidencia. M-02: el último smoke quedó bloqueado y su texto de fallback confundió umbral con cuantil; no hubo output ni evidencia de fallo del core. Respaldo guardado siempre identificado.

**Futuro propuesto.** Actualización supervisada y aprobación humana. Evolución temporal y acceso efectivo requieren nuevas series, movilidad, capacidad y demanda. No hay autoactualización ni autoedición activa.
